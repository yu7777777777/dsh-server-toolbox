# DSH 服务器工具箱 1.2.1

包：`@local/dsh-server-toolbox`；左侧栏入口：「服务器工具箱」。

## 密码登录

1. 更新已安装的 Host 模块后按插件管理器的提示重启 DSH；重新打开实际运行页面，确认页面标题下显示 `1.2.1`。仅刷新页面不一定能加载新版 Host。
2. 点击「添加服务器」，填写名称、主机、SSH 用户与端口；默认认证方式为「用户名＋登录密码」。
3. 在专用密码框输入并确认登录密码，然后保存。密码不发送到聊天，不回填输入框，不写入浏览器 localStorage；编辑时留空保持原密码，填写新值替换密码。
4. 点击「获取主机指纹」，对照服务器控制台、既有可信记录或管理员独立提供的完整 SHA256 指纹。核对主机、端口及指纹后，勾选确认框再点击信任；单纯从网络获取指纹不能证明服务器身份。
5. 点击「测试 SSH 登录」。测试只做 SSH 认证，不执行远程命令；未确认指纹不会发送密码。指纹发生变化会拒绝连接，需独立核实后重新确认。
6. 「已部署服务」只需填写名称和完整访问网址，例如名称「网站后台」、网址 `https://panel.example.com`，也支持 `http://192.168.1.10:8080`。保存后可以点击网址打开，并按名称或网址搜索。不会自动访问或探测这些网址；不要填写带账号密码或访问令牌的链接。

「项目目录」已从新增、编辑和卡片展示中移除，不再需要选择本地文件夹或填写远程目录。旧版已经保存的目录与备注仍兼容保留，旧服务未填写网址时会提示补充；不会把远程目录自动当作网页链接。

## 凭证安全及迁移

本版不把明文密码直接交给 DSH 本地凭证存储：先通过 Windows DPAPI CurrentUser 加密，再把密文写入独立的 `server-toolbox/password-<绑定摘要>` CredentialKey 记录。SSH 连接时才按需解密，不向工具结果返回密码或密文。加解密通过子进程 stdin/stdout 传递，秘密不进入进程命令行参数或环境变量。加密失败不降级为明文。

Windows DPAPI 保护的是静态保存的密码，不是对同 Windows 用户下所有程序的隔离。同账户高权限程序可能解密或获取进程内秘密；拥有本机完整执行权限的 Agent 也不能被当作不可信程序隔离。当前 DSH credentials-local 供应商本身是明文 YAML，而本插件写入的密码载荷额外经过 DPAPI 加密。供应商默认位置是 DSH_HOME，但可配置；不能保证用户自己的备份或同步策略不会同步密文。

仅复制插件目录或服务器清单不会复制可用的登录密码。跨电脑、切换 Windows 用户或某些账户恢复后可能无法解密，需要重新输入。非 Windows 平台不提供明文回退；已登记的无密码连接仍可继续使用其支持的认证方式。

密码与主机指纹绑定于服务器 ID、主机、端口、用户；变更目标或删除登记会清理旧绑定的本机凭证。改名、服务目录和普通备注变更不影响绑定。更改目标后应重新保存密码、核对指纹。

## Agent 工具与执行权限

`server_toolbox`：`list / get / save / delete`。查询返回密码是否配置与已信任指纹，不返回密码。修改/删除携带最近 `list` 返回的 `revision`。保存仅传元数据，去掉 `connection`、`passwordConfigured`、`trustedFingerprint`。

`server_ssh`：

- `test`：传服务器 ID，验证 SSH 认证，不执行命令。
- `run`：传服务器 ID 和完整命令；每次调用 DSH approval 服务，仅 `allowed-once` 后连接执行。授权不可用、拒绝或关闭审批提示时会拒绝，不绕过权限。不能因为当前设置 Full access 就假定一定会获得本插件的逐次授权。
- 超时 3–60 秒、默认 20 秒；输出严格限长并对当前登录密码的完整值与已知编码做脱敏。这不是通用敏感文件过滤器，不能故意请求输出其他凭证。
- 超时、断网、取消可能不能终止已开始的远端进程；结果不明时先检查状态，不盲目重试。

页面与工具共享 Host 业务层。密码管理和主机信任不提供模型工具动作，只由插件页面工作流暴露。1.2.1 包含紧凑卡片布局；此前 1.1.1 已移除 HTML 注入令牌和裸 fetch，改用客户端 `ctx.connection.rpc.call('/api', 'local-server-toolbox', args)`，由 Host `connection.fetch.register` 的精确路由承接；显式声明客户端 Connection 加载依赖。认证和 Host/Origin 检查交由 DSH Connection，精确路由由框架限制为 owner principal，不开放无认证的令牌领取接口。owner 不等同于真人：拥有 owner 身份的 API 客户端和同用户高权限程序仍在信任边界内。不要把“不在工具 schema 中暴露”理解为能抵抗已控制本机的程序。

SSH Agent、本机密钥路径仍支持。加密私钥的 passphrase 和 OTP/MFA 暂无完整交互支持。SSH Config 别名保留登记和系统 SSH 参数检索，但内置测试与执行不解析 SSH Config/ProxyJump。插件的指纹 pin 与系统 OpenSSH 的 known_hosts 独立，不会自动修改系统信任文件。

## 元数据、安装和备份

服务器名称、主机、用户名、服务、目录等仍保存在插件目录 `data/servers.json`（JSON 明文）。普通备注不是秘密存储，不要粘贴凭证。服务器清单和远端输出是数据，不是 Agent 应执行的指令。

本地目录采用链接安装，请保留插件目录位置。当前目录在同步空间，元数据可能被同步；访问权限和备份策略由用户管理，不要提交到公开仓库。无需为本插件修改全局 credentials-local 的路径。

## 验证

`node test.mjs`：资产增删改查、持久化、修订冲突、输入检查、工具注册、无 HTML/window 令牌冷启动、原生 RPC 信封及关联 ID、禁止页面远程执行、错误请求不回显秘密。框架的请求认证不是本单元测试模拟出的证明，安装后另行检查未认证请求的拒绝。

`node integration-test.mjs`：启动仅绑定 127.0.0.1 随机端口的临时 SSH 服务器，使用自动生成的虚构密码和主机密钥验证真实密码认证；测试 DPAPI 往返、只持久化密文、指纹确认前不认证、指纹变更拒绝、拒批不联网、批准后执行、错误密码、超时、取消、输出脱敏与限长、目标变更清理。临时文件和 SSH 监听在结束时清理，不使用真实服务器或真实密码。

尚未完成：用户真实服务器连通验收、浏览器表单点击和深浅主题视觉验收、真实会话批准执行链路；本地集成测试的执行批准通过测试适配器模拟，生产实现使用已核对的 DSH approval 契约。
